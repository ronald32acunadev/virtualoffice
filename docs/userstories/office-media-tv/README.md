## Confirmed facts, decisions & scope boundaries

- **Confirmed facts (verified in codebase on 2026-11-23)**:
  - `apps/server` is a local Fastify + WebSocket + `node:sqlite` server (`apps/server/src/http/app.ts`, `apps/server/src/persistence/sqlite/sqlite-office-repository.ts`, `apps/server/src/office/application/office-service.ts`).
  - `apps/web` is a React 19 + Vite + `@react-three/fiber` + `@react-three/drei` (`^10.7.9`) + `three` client with two views: `/office` (`OfficeView.tsx` → `OfficeScene.tsx` → `OfficeRoom.tsx`) and `/workspace` (`WorkspaceView.tsx`).
  - The default isometric camera (`DEFAULT_CAMERA_POSITION = [0, 17, 21]`, `DEFAULT_CAMERA_TARGET = [0, 0.5, 0]`) faces the back wall center pier (`x in [-4.0, 5.2]`, inner face `z = -15.0`, height `5.4`). Currently `whiteboard-main` occupies `[0, 0, -14.5]`.
  - `apps/web/src/scene/officeTheme.test.ts` asserts that every entry in `PROP_PLACEMENTS` stays inside `OFFICE_HALF_SIZE` (`15`) and never overlaps any boss or employee desk (`overlapsAnyDesk`).
  - Full web apps for Spotify, YouTube Music, and Apple Music block cross-origin framing via `X-Frame-Options` / CSP `frame-ancestors`; only their official embed endpoints (`open.spotify.com/embed/...`, `www.youtube.com/embed/...`, `embed.music.apple.com/...`) can render inside iframes.
- **Approved product decisions**:
  - Embedded in-app player approach (Option 2) with an Android-style app/provider chooser supporting **Spotify**, **YouTube Music / YouTube (music and video)**, and **Apple Music**.
  - Playback renders directly inside the **3D TV mounted on the office wall** using `@react-three/drei` `<Html transform>`, so YouTube videos and official music embeds play inside the TV screen.
  - Users paste links (tracks, albums, playlists, YouTube videos) and can save favorite stations in Virtual Office for 1-click replay.
- **Scope boundaries & exclusions**:
  - **No OAuth, developer API keys, or OS media/MPRIS integration** in this feature.
  - **Strict iframe allowlist**: only canonical `https://` embed URLs generated by the parser (`open.spotify.com/embed/...`, `www.youtube.com/embed/...`, `embed.music.apple.com/...`) are accepted or rendered; arbitrary URLs and non-HTTPS schemes are rejected.
  - **Browser-session playback reality**: Spotify and Apple Music embeds rely on the user's active browser login session for full-track playback and may fall back to 30-second previews when signed out; this is an upstream provider constraint, not controlled by Virtual Office.
  - **No new npm dependencies**.
  - **Controls live in `/office`** (HUD + 3D TV), not `/workspace`.

Verification levels: Vitest unit and HTTP/WebSocket integration tests in `apps/server` and `apps/web` (using isolated `:memory:` SQLite databases and deterministic fetch stubs), `npm run typecheck`, `npm test`, and `npm run build`, plus manual browser verification in `/office` (Day and Evening moods).

## US-01 — Parse and validate Spotify, YouTube / YouTube Music, and Apple Music URLs into canonical embed descriptors

As the owner, I want Virtual Office to recognize links from Spotify, YouTube / YouTube Music (including videos and playlists), and Apple Music and convert them into safe official embed descriptors, so that valid links play reliably and invalid or unsafe URLs are rejected with clear feedback.

- `US-01 / AC-01`: Given a valid Spotify URL (`https://open.spotify.com/track/<id>`, `album`, `playlist`, `episode`, `show`, `artist`, including optional `/intl-xx/` locale prefix and query params) or URI (`spotify:track:<id>`), when parsed by the media URL parser, then it returns `{ provider: "spotify", mediaKind: "audio", canonicalUrl, embedUrl: "https://open.spotify.com/embed/<type>/<id>?utm_source=generator", fallbackTitle }`.
- `US-01 / AC-02`: Given a valid YouTube or YouTube Music URL (`youtube.com/watch?v=<id>`, `music.youtube.com/watch?v=<id>`, `youtu.be/<id>`, `youtube.com/shorts/<id>`, `youtube.com/live/<id>`, `youtube.com/embed/<id>`, or `youtube.com/playlist?list=<listId>` / `music.youtube.com/playlist?list=<listId>`), when parsed, then it returns `provider: "youtube_music"`, `mediaKind: "video"` (for standard YouTube video links) or `"audio"` / `"video"` consistently indicated from host/type, and a canonical `https://www.youtube.com/embed/...` URL preserving optional `list` parameter without leaking arbitrary query parameters.
- `US-01 / AC-03`: Given a valid Apple Music URL (`https://music.apple.com/<storefront>/(album|playlist|song|station)/...`, with optional `?i=<trackId>`), when parsed, then it returns `{ provider: "apple_music", mediaKind: "audio", canonicalUrl, embedUrl: "https://embed.music.apple.com/<storefront>/...", fallbackTitle }`.
- `US-01 / AC-04`: Given an unsupported host, non-HTTPS scheme (`javascript:`, `http:`, `data:`), malformed path, path traversal (`..`), empty ID, or a provider hint that mismatches the URL's detected provider, when parsed, then it returns a structured validation error without producing an embed URL.
- `US-01 / AC-05`: Given the server-side metadata resolver with an injected `fetch` dependency, when resolving title/thumbnail via official oEmbed endpoints (`open.spotify.com/oembed`, `www.youtube.com/oembed`) for a valid descriptor, then it returns the resolved title and optional HTTPS thumbnail URL; when the network request times out, fails, or returns non-2xx/invalid JSON (or for Apple Music without oEmbed), it gracefully falls back to `fallbackTitle` and `thumbnailUrl: null` without throwing.

## US-02 — Persist office TV playback state and saved stations in SQLite with REST API and WebSocket sync

As the owner, I want the active office TV playback state and my saved favorite stations persisted in SQLite and synchronized in real time via REST and WebSocket, so that my music/video setup survives reloads and stays consistent across open tabs.

- `US-02 / AC-01`: Given `SqliteOfficeRepository` opening a new or existing `office.sqlite` database, `media_state` and `media_presets` tables are created idempotently without affecting existing `employees`, `messages`, `approvals`, or `projects` rows.
- `US-02 / AC-02`: Given an authenticated `GET /api/state` or `GET /api/media` request, the server returns the persisted `media` (`MediaPlaybackState | null`) and `mediaPresets` (`MediaPreset[]`, newest first).
- `US-02 / AC-03`: Given an authenticated `PUT /api/media/playback` request with `{ url, provider?, title? }`:
  - Valid input parses and validates the URL, resolves best-effort metadata (preferring an explicit non-empty trimmed `title` if supplied), saves `media_state`, broadcasts `{ type: "media_updated", media }` to `/ws` subscribers, and returns `200 { media }`.
  - Invalid/unsupported URLs or mismatched `provider` return `400` with `{ error: { code: "validation_error", ... } }` and leave persisted `media_state` unchanged.
- `US-02 / AC-04`: Given an authenticated `DELETE /api/media/playback` request, the server clears `media_state`, broadcasts `{ type: "media_updated", media: null }`, and returns `200 { media: null }`.
- `US-02 / AC-05`: Given authenticated `POST /api/media/presets` (`{ url, provider?, title? }`) and `DELETE /api/media/presets/:id` requests:
  - Valid `POST` persists a new preset (or rejects invalid URLs with `400`), broadcasts `{ type: "media_presets_updated", presets }`, and returns `201 { preset, presets }`.
  - `DELETE` removes an existing preset, broadcasts `{ type: "media_presets_updated", presets }`, and returns `200 { deleted: true, presets }`; unknown IDs return `404` (`not_found`) without mutating state.
- `US-02 / AC-06`: Given `apps/web` state management (`api/types.ts`, `api/client.ts`, `state/officeReducer.ts`, `state/OfficeProvider.tsx`), initial snapshot hydration and `media_updated` / `media_presets_updated` WebSocket events update `state.media` and `state.mediaPresets` without regressing existing employee/boss/approval state transitions.

## US-03 — Mount an interactive 3D Media TV on the office back wall with live in-TV playback and camera focus

As the owner, I want a widescreen 3D TV mounted on the office back wall that plays the active YouTube video or Spotify / Apple Music player directly inside the TV screen (and shows a standby screen when nothing is selected), so that music and video live naturally inside the 3D virtual office.

- `US-03 / AC-01`: Given `OfficeRoom.tsx` and `officeTheme.ts`, a wall-mounted widescreen 3D TV (`OfficeMediaTv`) is placed on the back wall center pier (facing the default camera), and `whiteboard-main` is repositioned to an open wall location so that all `PROP_PLACEMENTS` stay within `OFFICE_HALF_SIZE` and pass `overlapsAnyDesk` with zero collisions.
- `US-03 / AC-02`: Given `state.media === null`, the 3D TV displays a standby screen inside its bezel (`Office TV — Standby`) with a clickable action to open the media selector drawer, and its power LED shows muted standby styling.
- `US-03 / AC-03`: Given `state.media !== null`, the 3D TV renders the validated `embedUrl` directly inside the TV screen via `@react-three/drei` `<Html transform>` (supporting live YouTube video playback as well as Spotify and Apple Music embeds), sets the TV bezel LED accent to the active provider's color (`spotify`, `youtube_music`, `apple_music`), and provides a compact screen header bar with provider badge, title, `Focus TV`, `Change`, and `Off` controls.
- `US-03 / AC-04`: Given `OfficeScene.tsx` (`CameraRig`) and `camera.ts`, triggering TV focus smoothly animates the camera to frame the back-wall TV head-on (`TV_FOCUS_CAMERA_POSITION`, `TV_FOCUS_CAMERA_TARGET`), while manual orbit/pan cancels the animation and `Reset view` restores the full office overview as before.
- `US-03 / AC-05`: Given `apps/web` pure helpers for TV visuals and camera presets (e.g., `mediaTv.ts`, `camera.ts`), provider branding metadata, iframe attributes/allowlist guard, and camera focus targets are deterministic, Node/Vitest-safe, and verified by unit tests.

## US-04 — Add Android-style provider chooser drawer and saved stations controls to the Office HUD

As the owner, I want an app-chooser panel in `/office` where I pick Spotify, YouTube Music / Video, or Apple Music, paste a link to play on the 3D TV, and save or switch between favorite stations, so that managing office music and videos takes only a couple of clicks.

- `US-04 / AC-01`: Given `OfficeView.tsx`, the `.office-hud` toolbar includes a `TV / Music` toggle button (showing an active indicator and current title when playing) and, when media is active, a `Focus TV` quick button. Clicking the HUD button or the 3D TV standby/change control toggles the Office Media Drawer.
- `US-04 / AC-02`: Given the Office Media Drawer (`MediaDrawer.tsx`), an Android-style app chooser displays selectable tiles for **Spotify**, **YouTube Music / Video**, and **Apple Music**. Pasting a valid URL from another supported provider automatically detects and highlights the matching provider (while letting the user switch tiles freely).
- `US-04 / AC-03`: Given a URL entered in the drawer (with optional custom label):
  - Clicking **Play on TV** submits `PUT /api/media/playback`, displays a loading/error state if validation or the request fails, and updates the 3D TV immediately on success.
  - Clicking **Save station** submits `POST /api/media/presets` and appends/refreshes the station in the saved stations list.
  - Clicking **Turn off TV** (when media is active) submits `DELETE /api/media/playback` and returns the 3D TV to standby.
- `US-04 / AC-04`: Given saved stations in the drawer, each row displays its provider badge, title, a 1-click **Play** action (calling `PUT /api/media/playback`), and a **Remove** action (calling `DELETE /api/media/presets/:id`).
- `US-04 / AC-05`: Given Day and Evening office moods (`data-office-mood`), the Office Media Drawer, provider tiles, and HUD controls remain legible and responsive without blocking camera orbit when closed, and pressing `Escape` closes the drawer.
